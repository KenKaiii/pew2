# pew2

Mobile remote control for **desktop coding agents** (Claude Code, Codex, Gemini CLI, GG Coder).
The agent runs on the user's machine over the [Agent Client Protocol](https://agentclientprotocol.com);
the phone is a client that watches the same session, prompts it, and answers its permission
requests. **Transport + UI, not an agent.**

- `packages/protocol` — Zod schemas for provider manifests and the daemon↔relay↔app envelope; authoritative for both sides (`schemas/*.json` is autocomplete only, synced by hand).
- `packages/daemon` — spawns agents, speaks ACP over stdio, owns the seq'd session log, warm spares, probe cache, config prefs, and the `pew2` CLI.
- `packages/relay` — Cloudflare Worker + DO, one per pairing; routes opaque frames between `daemon`/`app` roles, persists events in DO SQLite for replay.
- `packages/app` — Expo/React Native client. `providers/*.json` — one manifest per agent; adding a file is the whole integration.

**Flow:** app `session.prompt` → relay → daemon → ACP `session/prompt`. Agent `session/update` →
`SessionLog.append()` stamps a gapless `seq` → broadcast to **all** clients. ACP is
one-client-to-one-agent, so a phone and a desktop share a session only because the daemon owns
the log — and reconnecting clients replay from a cursor because **ACP never re-sends**. Do not
"simplify" that away.

## Gotchas — daemon

- **Register the permission resolver *before* notifying the UI** (`acp/connect.ts`). A caller answering synchronously finds no pending entry and the agent hangs — the "tap Approve, nothing happens" bug.
- **Child processes need `error` *and* `spawn` listeners.** An unresolvable command emits `error` asynchronously; unhandled it kills the daemon and every other session. Providers are PATH-checked at load so a missing binary reads as unavailable.
- **Agent failures arrive twice and the useful half is in `data`.** An agent streams its error as message text *then* rejects the turn. `humanError()` (`errors.ts`) normalises every failure at the one point all transports share; the real reason sits in JSON-RPC `data.details`, sometimes double-encoded, so `RequestError.message` alone throws it away.
- **A clean exit is not an error.** Closing a session kills the child, so `kind: "exit"` fires with a null/zero code on every normal finish. Only non-zero renders.
- **Under launchd cwd is `/`, and agents treat cwd as project root.** GG Coder died on `mkdir '/.gg'`. `resolveWorkspace()` (`workspace.ts`) is the single default: explicit → `PEW2_WORKSPACE` → daemon cwd → home. Session start *and* the capability probe both go through it; a third spawn path without it reintroduces the bug.
- **Warm spares: check `spares.has(id)` before booting; gate readiness on `spareReady`, not `warming`.** A disk-cached probe skips the boot path, so the wrong flag either spawns a duplicate agent or blocks a session open on a history read.
- **`config-prefs.json` is one file shared by all providers** — read-modify-write it. The probe cache is overwritten wholesale by the next probe, which is why user model/mode choices cannot live there.
- **A model is per conversation, so two records exist.** `config-prefs.json` seeds the *next new* session; `session-prefs.json` (keyed by provider + agent session id) is replayed on `session/load`, because ACP resumes a transcript but hands back the agent's *default* selectors — leaving it alone reverted the model on every switch away and back. Never apply the provider preference to a resume: that would rewrite a conversation started at the desk to match the phone's last pick, so a session with no record of its own keeps whatever the agent reports.
- **`session.started` carries `agentSessionId` for new sessions too.** Daemon session ids are assigned before the agent answers, so without it the next history probe listed the conversation already on screen a second time as a stub — and reopening *that* copy reloaded from disk and lost the session's settings.
- **Session ids die with the daemon process; the app's session list does not.** So the provider announcement carries `activeSessions`, and `hello` triggers one. `needsResume()` (`agentHistory.ts`) is the single rule for opening a conversation: the agent's own copy, or one the daemon no longer holds, is reloaded via `session.resume`; anything else renders from memory. Without it a restarted daemon answered `Unknown session '<id>'` on the next prompt. An undefined list (older daemon) means *assume live* — guessing dead would reload every conversation.
- **Projects are folded from the *uncapped* session list, before `SESSION_HISTORY_LIMIT`** (`projects.ts`, `acp/connect.ts`). The capped list is a recent-work window, so grouping *that* offers only the repos touched this week as if they were all that existed — a fortnight in one project hides every other. `listSessions()` therefore returns three views of one answer: capped `sessions` (the only ones whose message counts are worth reading from disk up front), complete `projects`, and `all`, held in `projectHistory` so choosing a project is answered without spawning the agent again. Counts are hydrated per project on demand (`acp/messageCounts.ts`), never for every project at probe time — that is hundreds of file reads for the one the user will pick.
- **`workspace.status` accepts a `cwd`, and that is not a hole.** It is honoured only when `knownProject()` says this daemon already announced that path for that provider, so it cannot probe whether some other directory exists. It is what lets the context row name where the *next* prompt lands before any session exists.
- **Two transports, one handler.** `handler.ts` owns every message case; `server.ts` (LAN) and `relay-client.ts` (remote) only supply `reply`/`broadcast`. A case added to one makes local and remote drift.
- **Relay must use `ctx.acceptWebSocket()`, not `server.accept()`** — only that permits Hibernation, which makes idle sessions free. It also **requires `deviceId` on `/connect`** (400 otherwise, seen as a socket that never opens) and **must forward `hello` after replaying cursors, not return** — it is the daemon's only signal an app joined, else the phone shows an empty app list forever.
- **The daemon stamps `folder` (and `providerId`) onto `session.idle`.** Only this machine has the path, and the phone must name the project in a notification for a session it is not showing — a conversation the app started has no `cwd` of its own to derive it from. `folderName()` (`workspace.ts`) is the one place a path becomes a name.
- **Images are answered as a `reply`, never as a session event** (`images.ts`). Only this machine can read the path an agent names (`resource_link`, `![](.gg/generated/x.png)`, tool-call content), so `image.fetch` inlines the bytes on demand — putting them in the seq'd log would re-download every picture on every reconnect. The path comes from the *agent*, so it is realpath'd (roots too: on macOS `/tmp` is a symlink) and confined to the session cwd plus tempdir; 8MB ceiling keeps a frame under the DO's 32 MiB receive limit. Local history loaders flatten messages to text, so they must lift image blocks out separately or a resumed thread loses every screenshot.
- **Attachments go the *other* way from images, and land in the tempdir, never the project** (`attachments.ts`). The phone inlines bytes in `session.prompt`; the daemon writes them to `<tmpdir>/pew2-attachments/<sessionId>/` — not cwd, which is a git repo whose uncommitted count the context row shows, and which `git add .` would then commit. tmpdir is already in `allowedImageRoots()`, so the echoed copy renders through the existing `image.fetch` path with no second containment rule. The name comes off a phone, so it is sanitised to one segment (runs of dots collapse: stripping a *leading* `..` still leaves `.._.._etc`) and index-prefixed, because two camera-roll photos are very often both `image.jpg`.
- **The prompt block is chosen from `promptCapabilities`, and a `resource_link` is not enough on its own** (`acp/promptBlocks.ts`). Sending a block an agent never advertised is a protocol error, so: image inline only when it claims `image` (Claude Code does; GG Coder and echo do not), embedded `resource` for small text only when it claims `embeddedContext`, else a link. But a link is *advisory* — GG Coder answers "I can't see an attached file" to a prompt whose `resource_link` names a file it could have read — so anything delivered as a link is **also named with its path in the text block**, the one type every agent must handle. Without that, attaching a file to a non-vision agent silently did nothing.
- **The pairing token is a bearer secret (32-char floor), not auth; there is no E2EE.** Unpaired sockets are rejected at the HTTP upgrade so a bad token never connects; `/health` stays open so `doctor` distinguishes "not running" from "unpaired". `PEW2_TOKEN` overrides the stored token and is never written to disk; `PEW2_HOME` relocates `~/.pew2`.

## Gotchas — app

- **Turn ids are `${sessionId}:${seq}`.** `seq` restarts at 0 per session, so seq alone collides and React merges unrelated turns.
- **The project selector is the drawer's second axis, and it does two jobs at once** (`projects.ts`, `ui/ProjectSelect.tsx`, `ui/ProjectMenu.tsx`). The history list is a recent-work switcher, so a repo left alone for a fortnight has no rows in it and could not be reached from the phone at all; choosing a project narrows that list *and* decides where the next session opens (`session.start` carries `cwd` from `projectRef`). Selection is per provider — projects belong to an agent, so one global choice would carry a path the next agent has never opened. Matching is `cwd`, falling back to the daemon-stamped `folder` **name**: a conversation this app started never had a `cwd`, and without the fallback it vanishes out of the project it was started in. The fetch is an effect, not part of `selectProject`, so a reconnect re-asks — the socket dies on every backgrounding and a request written to the dead one is never answered. `projectsForProvider()` unions the daemon's list with projects visible in `sessions` so an older daemon (no `projects` field) still offers something, stamping the unannounced ones from `startedAt` — undated, a repo opened a minute ago sorts *last* in a menu that promises newest first. Two further traps: the in-flight project lives in `State.loadingProject`, **not a ref**, because it chooses between the skeleton and "No conversations in pew2 yet" and a ref is read during a render nothing schedules; and the menu is closed by an effect on `open`/`activeProviderId`, since the drawer is only translated off screen and an open menu otherwise waits on top of the history — holding another agent's projects after a switch.
- **"New chat" asks where, and aims the next session through the *same* project selection the drawer uses** (`ui/NewChatSheet.tsx`). It used to start one on tap, which always landed wherever the agent happened to be — right often enough to feel fine and unfixable from the phone the rest of the time. Two steps, because naming the current project is the common case and should not cost a list; the second step is hidden entirely when there is nothing to switch to. `startNewChat` calls `daemon.selectProject` rather than keeping a private "where the next chat goes", since two notions of the current project disagree the moment either is used. The sheet resets to step one **on open, not on close** — `Sheet` stays mounted for its exit animation, so clearing it on close swaps the list back to step one while the card is still sliding down, in full view. `Sheet`'s `onBack` replaces the close button rather than joining it — two buttons push the title off centre — and the scrim still dismisses. **The two steps are a push, not a swap**: both panes stay mounted and absolutely positioned in one box, the hidden one `pointerEvents="none"`, sliding a measured card width while the card's own height springs between two measured heights. That needs *two* `Animated.Value`s started together — transform and opacity are native-driven, `height` cannot be — and `Sheet` cross-fades its title and header glyph to match, since a header that cuts while the panes travel is what gives away there were two cards.
- **The drawer's "new chat" lives beside "Latest chats", not in the header, and only with a project chosen** (`ui/Sidebar.tsx`). A button above both the app chips and the project selector cannot say which project it means — it started one wherever the agent last was, misleading exactly when it matters. Beside the heading, under a named project, it is unambiguous, and it takes `cwd` through the same `startNewChat` the sheet uses. It springs in on selection rather than popping: an element materialising next to a heading already being read registers as a glitch, not an offer — and the header row carries a `minHeight` for the chip whether or not it is there, or that spring lands on top of the whole list jumping down.
- **Clearing `workspace` is not the same as re-asking for it — hence `workspaceNonce`.** The request is driven by session, provider and chosen project, so it re-fires when one of those changes. Leaving a conversation changes *none* of them when the project is already the chosen one, which is exactly "+ New chat" from a selected project: the row was cleared, every dependency stayed equal, nothing re-asked, and the project simply vanished until a prompt created a session. `leave()` and `open()` bump the nonce — opening a *fixture* is the same trap, since it leaves `sessionId` and the provider exactly as they were. `select()` does not need to: it always changes `activeProviderId`.
- **The context row is one line by contract, and never wraps** (`ui/ContextBar.tsx`, `contextUsage.ts`). The dock's height is computed around it, so a second line pushes the composer down and re-lays out the thread. Every label is `numberOfLines={1}`, every cell is `flexShrink: 0`, and **only the project name is elastic** — it is the one item whose meaning survives truncation (`acme-st…` still names the project; `9 uncommi…` is gibberish and a clipped percentage is a *different number*). A shrinkable child inside a rigid parent squeezes nothing, so the `elastic` flag is carried on the item and applied to its wrapper cell too. Icons were removed for the same budget: a folder glyph beside a folder name is a tautology costing ~20pt.
- **Context percentage comes from ACP `usage_update`, which not every agent sends.** Claude Code emits `used`/`size` (plus `cost` and a `_claude/rateLimit` warning in `_meta`), and GG Coder now does too; an agent that sends none gets **no reading at all rather than 0%** — a confident zero is worse than silence. The window is per *model* (1M on one, 272k on another), so two readings are only comparable within a session that has not switched. `readUsage()` validates the numbers because they cross a wire from a process pew2 does not control, and the fold filters on `sessionRef.current`: the daemon broadcasts every session, and another project's meter is not this one's. It is also the one signal that survives replay: unlike `busy`, the last reading is the session's *current* state, so `replayFold` carries it — skipping it blanks the meter on every reconnect until the agent happens to send another.
- **Filter `session.event`/`session.idle` against `sessionRef.current`.** The daemon broadcasts every session to every client; an abandoned one still streaming otherwise renders into the conversation on screen.
- **Replay and the live stream overlap** — drop events at or below the per-session cursor (`cursors.ts`). Replayed events take the same `onmessage` path as live ones, so there is only one rendering path.
- **A replay batch must not set `busy` or raise `permission`** (`replayFold.ts`): those describe a turn happening *now*. A replay's last chunk is not work in progress (perpetual spinner) and its permission was answered long ago (phantom approve sheet). Likewise **hold the skeleton until `session.started`**, or the thread flashes empty.
- **Map `user_message_chunk`, not just live prompts** (`chunks.ts`). GG Coder replays user turns that way; unmapped, every user turn vanishes and agent chunks coalesce into one wall of text. Replayed history also carries internal markers (`[Previous conversation summary]`, compaction acks) that must be filtered.
- **Merging chunks is not concatenation — the *seam* decides** (`chunkJoin.ts`). ACP says nothing about whether a chunk continues the last one, and agents differ: Claude Code streams tokens (`"Let me check"` + `" that."`), while an agent narrating around tool calls sends whole messages (`"Let me check."` + `"Let me see if it's green."`) — tool calls create no turn, so those coalesce into one bubble and rendered as `"Let me check.Let me see…"`. So: whitespace either side of the seam means continue (a stream spaces itself); a sentence *ending* against a capital or markdown marker gets `\n\n`. Per-seam, not per-provider, so an agent that streams sometimes and batches other times is right both times and a new agent needs no table entry. Requiring a real character *before* the stop is load-bearing twice over: `"3."` + `"14"` is one number, and agents emit a bare `"."` as its own token — both would otherwise split a sentence, which is the direction to stay conservative in.
- **A turn is empty only when it has no text *and* no images** (`chunks.ts`). An image generation tool's result is tool-call content with no message chunk at all, so text-only emptiness checks dropped it — the blank-chat bug. Pictures ride beside the text (`turn.images`), not spliced into the markdown, and `Turn`'s memo compares that array by identity because inline base64 is megabytes. Fetches are deduped by uri in a ref, since a recycling list mounts the same image repeatedly. Saving lives in the full-screen viewer, not on the thumbnail, where a button fights the scroll: `saveImage.ts` stays Expo-free, `ui/imageSaver.ts` binds media-library/sharing, and a denied permission falls back to the share sheet rather than losing the picture.
- **Tool calls are the live indicator, and they exit with the turn** (`activity.ts`). `foldActivity` runs at the *top* of the `session.event` case and every early return carries it — a tool call is not a chunk, so returning `prev` anywhere drops the updates the footer exists to show. The fold returns the same object when nothing changed, or streamed prose re-renders the footer per word. **A turn alternates — tools, prose, more tools — so `Activity.speaking` is ordering, not a latch**: agent text sets it and `currentTool` goes silent (the answer is its own proof of life; a tool name beside streaming prose describes work already finished), the next tool call clears it and the line returns. Speech is read through `readChunk`, so it means what the transcript actually rendered; thinking does not count, and a tool merely reporting `completed` must not yank the line back over an answer. The receipt that replaces it (`ui/TurnReceipt.tsx`) is measured, never guessed: the clock starts when the prompt leaves the phone, tokens appear only when an agent volunteered a figure in `_meta`, and a replay, a cancel or a session switch clears both — timing a minutes-old replayed turn from this device's clock would report it as instant. The footer element is never `null`: `ListFooterComponentStyle` carries the bottom reading inset and FlashList only lays it out around a footer that exists.
- **An agent error already on screen is *promoted* to the error role, not appended** (`errorDedup.ts`) — only the client knows what is rendered.
- **`session.idle` is the one broadcast that is *not* filtered to the open session.** It is the only signal a conversation left running has finished, which is precisely the one nobody is watching — so it is applied per session (`Session.busy`/`unread`, the drawer's dot) and only the open session clears the global spinner or re-asks for the git count. Agent text is buffered per session *above* that filter for the same reason, or a background turn has nothing to quote. Unlike `session.event` it is **never replayed** (the relay persists only seq'd events), so a `busy` session is cleared on reconnect — a turn that ended while the phone slept would otherwise pulse in the drawer forever.
- **Notifications: `notificationPolicy.ts` decides, `ui/notifier.ts` presents** — the usual pure/Expo split. Suppressed only when the app is foregrounded *on that session*; backgrounded or reading another project both earn a banner, titled `folder · agent` because the project is what tells two running agents apart. Local notifications only: JS is suspended seconds after backgrounding and the socket dies with it, so a turn landing after the phone locks needs the relay to push while no `app` socket is attached. A banner can launch the app cold, so the choice is held until the history list names the session — addressing an unknown id silently loses it. The banner carries an inline **reply** action (`setNotificationCategoryAsync`, iOS and Android both), which sends via `prompt(text, sessionId)` *without* switching threads: being pulled into another project for a one-line answer is what it exists to avoid. `opensAppToForeground: false` means the reply rides the existing socket — so if the app is not running it is delivered at next launch, the same bound as any local-only notification. Two guards: responses are deduped by interaction (the launch response is *also* handed to a listener, and sending one prompt twice is not idempotent), and `prompt` returns false when the target `needsResume` — a restarted daemon has dropped that id, so the text is put in the composer instead of answering "Unknown session".
- **The app cannot import `@pew2/protocol`** — Metro will not resolve its `.js`-suffixed TS imports and the *bundle* fails, not just a typecheck. So `attachments.ts` restates the size limits and `WireAttachment`, and a test compares them against `wire` (which `bun test` can load) so the copies cannot drift into the phone uploading what the daemon will refuse.
- **An attached photo is `origin: "device"`; the daemon's echo of it is not** (`images.ts`). Both are `file://`, but one is on this handset and the other on the desktop — the scheme cannot tell them apart, and fetching a phone path over the socket is a permanent error card. The optimistic turn uses `attachmentImages()` (flagged, rendered directly); replay maps `payload.attachments` via `imagesFromAttachments()` (unflagged, fetched), which is what makes an attachment visible on a second device and after a reconnect.
- **Dictation replaces the dictated tail, never appends** (`transcription.ts`). Each interim result restates the *whole* utterance, so appending yields "hello hello there hello there world"; the session remembers the draft it started from. `ui/speech.ts` requires `expo-speech-recognition` **lazily inside a `try`** — it is a native module absent from Expo Go, where a top-level import is a red screen on launch instead of a hidden mic. Intent (`wanted`) is tracked apart from `listening` because `start()` awaits a permission dialog: a tap in that window must cancel the session when it arrives, not start a second recogniser. Cancel on send, unmount and session switch, or the OS recording indicator stays lit.
- **The chip row sits *above* the composer's glass, not inside it.** The pill's contents are absolutely positioned against a height computed from the draft; threading a variable-height row through that math is what makes the text jump.
- **The transcript is FlashList v2 (`ui/ChatThread.tsx`) and owns its scroll position.** `maintainVisibleContentPosition={{ startRenderingFromBottom: true, autoscrollToBottomThreshold: 0.2 }}` is the whole mechanism. Never scroll imperatively from `onLayout`/`onContentSizeChange` — a state-driven scroll racing native repositioning is the jump this replaced; the only legitimate `scrollToEnd`s are the tap-driven jump-to-latest and the `threadBottom` effect, and the latter is **grow-only and never animated**. The dock changes height in both directions around the keyboard — it *grows* on dismiss, because `typing` goes false on `keyboardWillHide` and the context row remounts into it — so an animated catch-up runs its own curve across the keyboard's, and two animations landing at different times is the thread re-seating itself. Unanimated, the offset moves in the same frame as the layout that caused it; only slack below the last message is affected, so nothing is lost. **The keyboard is dismissed from `onScrollBeginDrag`**, not `keyboardDismissMode` alone: iOS's `"interactive"` never fires here (`useKeyboardLift` translates the pane entirely above the keyboard, so the finger never enters its frame) and `"on-drag"` waits for content to actually move, which reads as the keyboard hanging on. `"on-drag"` stays as the JS-free backstop. Contract: `keyExtractor` is `turn.key ?? turn.id` (an optimistic prompt keeps its key until the server echo adopts it, else the cell tears down mid-stream), every prop is memo-stable, and `key={sessionId}` remounts the list so `startRenderingFromBottom` re-arms. Cells recycle, so a mount no longer means "new message": `Turn` is memoized with no per-mount fade, the streaming dots are a `ListFooterComponent`, and an empty agent turn renders `null` (it is committed before its chunks arrive and would reserve a visible gap).
- **Slash command names end at the first non-word char, allowing `:` and `-`** (`slashCommands.ts`), because the composer lifts the command into a badge and rejoins later keystrokes after a space — matching the first word would assemble `/h elp` letter by letter. Normalise via `offeredCommands()` on *both* the probe list and the agent's `available_commands_update`, or the menu changes contents the moment the first prompt is sent.
- **`useDaemon` keeps `sessionRef`/`providerRef` mirrors.** React may invoke a `setState` updater twice, so updaters stay pure — never send a message or assign a ref inside one.
- **Pure modules stay Expo-free**: `pairingLink.ts`/`hapticsPolicy.ts` are testable, `pairing.ts`/`ui/haptics.ts` bind the native SDKs. Importing `expo-secure-store`/`expo-haptics` into the pure half breaks `bun test`, which cannot parse React Native's Flow syntax. Haptics are named by meaning (`sent`, `failed`, `finished`) and throttled — a failed turn errors *and* goes idle milliseconds apart, otherwise felt as one mushy double-buzz.
- **The conversation pane needs `zIndex: 1`** or the absolutely-positioned drawer paints over it and swallows touches; **`theme.gutter`/`theme.headerInset` are shared rails** or the title drifts from the hamburger as the drawer slides; **Composer subtracts `HALF_LEADING`** because iOS puts the whole leading above glyphs in a multiline `TextInput`.

## Workflows

- **Runtime is Bun** (`engines: bun >=1.2.0`). CI is ubuntu-only: frozen-lockfile install, typecheck, test.
- **The picker and dictation modules need a dev build, not Expo Go** (`expo-image-picker`, `expo-document-picker`, `expo-image-manipulator`, `expo-speech-recognition`) — as do `react-native-keyboard-controller` and `expo-glass-effect` already. **Two plugins must never claim one Info.plist key** — the later one silently wins, so the attach prompt ends up explaining something else. `expo-camera` owns `NSCameraUsageDescription` (pairing scanner *and* composer photos) and `expo-media-library` owns `NSPhotoLibraryUsageDescription` (attaching *and* saving); `expo-image-picker` therefore declares neither `cameraPermission` nor `photosPermission`.
- **Images are downscaled to a 1568px long edge before their bytes are read** (`ui/attachmentPicker.ts`). Never `base64: true` on the picker: that decodes the *original* 12MB photo into a JS string, which is the allocation the resize exists to avoid.
- **`Composer.harness.tsx`, `Sidebar.harness.tsx`, `NewChatSheet.harness.tsx` and `ContextBar.harness.tsx` render on web for a layout check** (`npx expo start --web`, point `index.ts` at it). Anything iOS-only must be optional-called or the whole tree blanks — `AccessibilityInfo.isReduceTransparencyEnabled?.()` in `Glass.tsx` is that fix.
- **After `npx expo install`, restart Metro.** A bundler started before the package existed keeps serving a graph without it, and the module reads as *missing at runtime* — `Cannot find module 'expo-speech-recognition'`, which the lazy require in `ui/speech.ts` then swallows into a silently hidden mic. Identical to a real integration failure, and it cost an hour once.
- **`ios.infoPlist` is written verbatim, so a `"//"` key ships in the binary.** Plugin props are read by code and drop unknown keys, so a `"//"` note there is inert (and is how `app.json`'s plugin entries are annotated) — but the same trick under `infoPlist` put a paragraph of English into the app's real Info.plist. JSON has no comments; prose about the plist belongs here.
- **`ITSAppUsesNonExemptEncryption: false` is load-bearing for builds.** pew2 speaks only wss/TLS, which is exempt standard encryption; without the declaration every EAS build stops for a manual App Store Connect answer.
- **Nobody's Expo account is committed** (`app.config.js`). `eas init` writes `owner`/`extra.eas.projectId` into `app.json`, which pins the repo to one person — wrong for a project that sells forking. Identity is layered in from `EAS_OWNER`/`EAS_PROJECT_ID` (CI) or the gitignored `eas-project.json` (a laptop); with neither, a fresh clone gets exactly what is committed. Also `promptToConfigurePushNotifications: false` in `eas.json`: notifications here are **local only**, and the prompt otherwise attaches a push key shared with unrelated projects.
- **`npm run daemon` is not the server.** It runs `index.ts`, which only prints JSON to stdout. The WebSocket server the app talks to is `bun run packages/daemon/src/server.ts` (8787, `PEW2_PORT`). The `echo` provider is a real ACP agent needing no key or network — the only way to exercise the pipeline offline.
- **Live app loop:** start that server, then `cd packages/app && npx expo run:ios` (a dev build — Expo Go can no longer load this app; see the native modules above); scan the QR the daemon prints. The bundler caches aggressively — if an edit doesn't appear, kill the app and relaunch it; a stale bundle looks exactly like a failed fix.
- **`npm run typecheck` chains three tsc passes** because the root config excludes the app, the relay needs `@cloudflare/workers-types` (globals conflict with Node's), and the app needs React Native's config.
- **Two integration checks need a server already running and are not in `npm test`:** `npm run relay:dev` then `npm run relay:check`; and, with the daemon up, `bun run packages/daemon/src/testing/e2e-check.mjs`.
- **`providers validate` proves only that the JSON parses.** `providers verify <id>` spawns the process, does the handshake, sends a real prompt and counts updates. Always finish with `verify`.
- **Remote needs a relay; without one it is same-Wi-Fi only.** `pew2 relay <url>` stores it; `pew2 pair` then prints `wss://`. `wrangler dev --local` silently breaks WebSocket upgrades (requests never reach the Worker, `relay:check` hangs), so `relay:dev` does not pass it.
- **`pew2` is not on PATH until `cd packages/daemon && bun link`** — the package is private with a `bin` entry, and without the link the pairing screen names a command the user does not have.
- **launchd starts the daemon with almost no environment.** The plist must state `PATH` explicitly (including bun's dir, or `npx` providers all appear missing), and any manifest arg that is a local script must be `./`-relative so the registry resolves it against the manifest. `pew2 service install|restart|uninstall`; logs in `~/.pew2/logs/`.
- **`pew2 setup --json` / `doctor --json` are the agent-facing surface.** `ok` is the stop condition, every problem carries a stable `id` and a runnable `fix`, and the exit code mirrors `ok`. Missing secrets and LAN-only are `warning`, never `error` — an agent cannot supply a secret or make a product decision and must not loop on one.
